# BrowserClaw Tool Cheat Sheet

Per-tool parameters and gotchas for all 50 registered tools. The MCP server always delivers the authoritative JSON Schema at runtime; this sheet records usage contracts and pitfalls that schemas do not express. Tool availability depends on the active profile: `core` (14 tools, default), `crawl` (12), `full` (50). Hidden tools auto-unlock by category on first call, or via `chrome_tool_docs { category, activateForSession: true }`.

## Cross-Cutting Contracts

1. **Batch first**: any predictable 2+ step sequence (login, search) goes into `chrome_batch_actions` — never split into per-step RTTs.
2. **Index lifetime**: 1-based indices are valid only for the current viewport without mutation; re-perceive after scroll or DOM change.
3. **Delta piggybacking**: `includeDelta: true` on interact/fill/batch returns DOM mutations in the same response, replacing a follow-up `chrome_read_dom`.
4. **In-memory media**: screenshots and media extraction stay in memory (base64 / streamed asset URLs); avoid disk writes in automation paths.
5. **Version notices**: an update hint is attached at most once per session, to the first tool response only; no need to relay it repeatedly.
