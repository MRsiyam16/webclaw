The browser tool that tells you whether it actually worked.

This is a fork of BrowserClaw with an evidence envelope, persistent element refs, and schema-typed extraction merged in. It drives your real, logged-in Chrome — your cookies, your session — and every mutating action comes back with a verdict and the evidence behind it, instead of a silent success.

What we built

Six changes layered on top of the fork, each one aimed at the same failure mode: a tool that reports success while the page quietly did nothing.

01

Evidence envelope

Every mutating action returns a verdict — applied, applied_unverified, noop, failed, or stale_ref — together with an outcome, the evidence behind it, and the postConditions that were checked. A click no longer returns a bare true; it returns what the page looked like after.

{ "verdict": "applied", "outcome": "…", "evidence": { … }, "postConditions": [ … ] }
02

Post-conditions with expected / actual / evidence

Assertions are declared up front and each one reports expected, actual, and the evidence that produced them. Two false negatives found in live testing are fixed: assertions are now evaluated against the PRE-navigation read-back, and pollable assertions settle-poll for up to 600ms / 4 attempts before being reported as failures.

{ "condition":"value_equals", "expected":"Cypher", "actual":"Neo4j", "passed":false }
03

Persistent refs

Element ids like e1 / e2 stay valid across re-renders, held in a WeakRef map and self-healed by fingerprint. Acting on a ref that has died returns a structured stale_ref with usable freshRefs instead of hanging or acting on the wrong node.

{ "verdict":"stale_ref", "recovery":{ "freshRefs":[ … ] } }   // 0.03s
04

Schema-typed extraction

browser_extract returns {data, missing, sourceRefs}. It pulled 40 typed rows from a real catalogue in one call. Values it cannot find go into missing — they are never invented — and every value in data points back at the element it was read from.

{ "data":{ "price":12.84, "title":"In Her Wake" }, "missing":[], "sourceRefs":{ … } }
05

Token discipline

Hard output budgets (default 120,000 chars, with an honest truncation marker when the cap is hit), delta-only re-reads on by default, and SimHash folding of near-duplicate list rows. The point is that a big page costs a small read.

get_markdown(maxLength: 500) → exactly 500 chars + truncation marker
before the fix: 40,828 chars returned, cap ignored
06

Perception for non-DOM surfaces + escape hatches

Set-of-Mark screenshots share one numbering between the image and the text map, safe-click-point resolution goes through elementFromPoint, and a zoom crop mode lets you look closer at a single label. When the DOM is the wrong tool, tier-3 javascript() and cdp_execute() are unlocked per session.

How it drives Chrome (and the Claude parallel)

webclaw lives in a Chrome MV3 extension and reaches the page through Chrome's own debugger protocol — chrome.debugger / CDP. This is the same trusted-input mechanism that Claude's Chrome control relies on for browser control; it is Chrome's own protocol for browser control, not a simulation layered on top of the page.

The practical consequence: clicks and typing are trusted (isTrusted: true) and survive frameworks that quietly ignore an element.click() — libraries that inject synthetic events into the page do not clear that bar. It also runs inside your real, logged-in Chrome, so it acts with your cookies and your session rather than a separate blank automation profile, and it uses focus emulation so it can work in a background tab without stealing focus. A native-messaging bridge exposes the same tools over local HTTP and MCP.

webclaw is not Claude, is not affiliated with Anthropic, and is built independently. The only thing stated here about Anthropic's side is the mechanism: Chrome's debugger protocol for browser control.

Proof from live testing

This was verified in a real Chrome, not only in unit tests. Six defects slipped past the test suite and were caught only by driving a live page; all six are now fixed. This list is the actual credibility behind the word "verified."

  • ✓Degenerate provenance refs — sourceRefs collapsed to the same node; fixed.
  • ✓No array extraction — a list of items came back as nothing; fixed (20 rows from page 2 of the catalogue, where the same call had returned only 2 rows one page earlier).
  • ✓Silently ignored zoom param — zoom was accepted and discarded; fixed (now returns a real crop box + scale).
  • ✓Legacy prose leaking beside the stale_ref verdict — an old "ACTION REQUIRED" string shipped alongside the new structured response; removed.
  • ✓Folding unproven — near-duplicate folding was assumed to work and hadn't been exercised; proven live.
  • ✓Item-root collapse + attribute matching — extraction lost the per-item root and mis-matched attributes; fixed.

Honest limits

  • 4 of 7 benchmark tasks re-run; T1 / T4 / T5 were skipped.
  • The settle-poll never actually fired for a genuinely >0ms-late update in the fixture.
  • The legacy active-tab fallback branch is unexercised.
  • Benchmark prompts were not byte-identical in length between arms.
